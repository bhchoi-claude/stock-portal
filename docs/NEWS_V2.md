## 0. 왜 다시 짜나

2026-09-18 브리핑 한 통이 문제를 다 보여줬다.

```
 4. 동박 4회
 5. 적층판 4회
12. CCL 7회 (처음)
```

셋은 같은 테마(동박적층판)다. 합치면 15회로 그날 1위인데 세 줄로 쪼개졌고
가장 많은 CCL 이 꼴찌였다. `저장소`·`동력` 같은 범용 명사도 섞였다.

**뿌리는 구조다.** 사전으로 먼저 자르고 남은 조각만 LLM 에 줬다. 사전의
`동박` 이 `동박적층판` 의 앞을 잘라 가면 LLM 은 `적층판` 만 본다. 이
설계는 LLM 비용을 아끼려던 것인데, 하루 원문이 200건 안팎이라 그 이유가
사라졌다.

## 1. 목표

사용자가 고른 것이다 (2026-09-19).

| | |
|---|---|
| 용도 | **테마 → 관련 종목 찾기**, **테마 급등 알림**, **나중에 매매 판단 입력** |
| 주기 | 하루 한 번, 장 마감 뒤 |
| 비용 | 하루 $0.2 이하 |

일일 브리핑은 목표에 없다. 새 결과물에서 거의 그대로 나오므로 둘지 없앨지는
나중에 정한다.

**'매매 판단 입력' 이 설계를 가장 엄격하게 만든다.** 백테스트가 그날 알 수
있던 값만 보고, 같은 날짜에 같은 값을 받아야 한다 (`PROJECT.md` 8.3).

## 2. 원칙

1. **원문을 통째로 읽는다.** 사전으로 미리 자르지 않는다
2. **테마는 종목을 묶는 단위다.** 상장 종목과 연결되지 않은 테마는 남기지
   않는다. 범용 명사를 **프롬프트의 부탁이 아니라 데이터로** 거른다 —
   `저장소` 에 묶이는 종목은 없다
3. **종목은 원문에 실제로 나온 것만.** 글자 그대로 원문에 있고 종목 마스터와
   맞는 것만 받는다. LLM 이 지어낸 종목명이 들어올 자리가 없다
4. **같은 테마는 날이 바뀌어도 같은 id 다.** 테마 사전과 별칭을 둔다.
   그래야 급등을 날짜끼리 견줄 수 있다
5. **한 번 낸 결과는 다시 계산하지 않는다.** LLM 은 같은 글에 매번 조금씩
   다르게 답한다. 저장하고 방식 버전을 붙인다
6. **미래를 보지 않는다.** 과거를 채울 때도 날짜 순서대로 돌리고, 그날까지
   만들어진 테마 사전만 쓴다

## 3. 하루의 흐름

### 분석 창

**직전 거래일 16:00 ~ 이번 거래일 16:00.** 장 마감(15:30) 뒤 30분 여유를 둔다.
주말·휴일에 올라온 글은 다음 거래일 창에 들어간다.

창에 거래일 하나가 붙는다. **거래일 D 의 테마는 D 16:00 에 확정된다.** 스윙
엔진의 계획(D 저녁 또는 D+1 아침)은 그 뒤라 미래를 보지 않는다.

### 단계

| | 무엇 | 누가 |
|---|---|---|
| 1 읽기 | 글마다 테마(라벨·근거 구절), 종목(원문 표기), 방향(긍정·부정·중립) | LLM, 50건씩 |
| 2 검증 | 종목명이 원문에 글자 그대로 있고 마스터와 맞는가 | 코드 |
| 3 묶기 | 그날 나온 테마 라벨을 서로, 그리고 기존 테마 사전과 묶는다 | LLM, 1회 |
| 4 판정 | 종목과 연결되지 않은 테마를 버린다 (원칙 2) | 코드 |
| 5 집계 | 테마별 언급 글 수, 채널 수, 연결 종목, 방향 | 코드 |
| 6 급등 | 기준선과 견준다 (4장) | 코드 |
| 7 발송 | 급등 알림 | 코드 |

**묶기는 라벨만 본다.** 원문을 다시 읽지 않는다. `동박`·`적층판`·`CCL`·
`동박적층판` 네 줄과 기존 사전을 받아 하나로 묶는다. 입력이 작아 싸다.

**판정은 그날 단위다.** 종목명 없이 테마만 말한 글도 있다 ("CCL 수요 급증").
같은 날 다른 글이나 테마 사전에서 그 테마가 종목과 이어져 있으면 남는다.

## 4. 급등의 정의

09-18 에 "평소 0.1회 → 42배" 가 줄줄이 나왔다. **이 규모에서 배수만으로는
뜻이 없다** — 지난주 한 번 나온 말이 오늘 세 번이면 21배다.

세 가지를 함께 본다. 값은 전부 `config/` 에 두고 **임시값**으로 시작한다.

| | 왜 |
|---|---|
| 오늘 언급 **글 수** | 한 글 안의 반복은 한 번으로 센다 |
| 오늘 언급 **채널 수** | 한 채널만 떠드는 것은 약하다. 지금 원문의 절반이 한 채널(급등일보)이다 |
| 기준선 대비 | 직전 20 거래일 평균. 처음 나온 테마는 글 수로만 본다 |

## 5. 데이터

**스키마 변경이다. 확인이 필요하다.** 새 테이블만 만들고 옛 것은 건드리지
않는다 (병행 운영).

| 테이블 | 무엇 |
|---|---|
| `theme` | 테마 사전. 이름, 처음 생긴 거래일 |
| `theme_alias` | 별칭 → 테마. `CCL` → 동박적층판 |
| `theme_stock` | 테마 ↔ 종목. 처음 이어진 거래일 |
| `message_theme` | 글 ↔ 테마, 방향, 근거 구절 |
| `message_stock` | 글 ↔ 종목 (검증을 통과한 것만) |
| `theme_daily` | 거래일 × 테마. 글 수, 채널 수, 방향 점수, 급등 여부 |
| `analysis_run` | 실행 기록. 창, 방식 버전, 모델, 토큰, 비용, 결과 |

모든 결과 행에 **`method_version`** 이 붙는다. 방식을 바꾸면 새 버전으로
새 행이 쌓이고, 백테스트는 버전 하나를 고정해서 읽는다.

## 6. 매매 입력을 위한 약속

- 거래일 D 의 `theme_daily` 는 D 16:00 실행 뒤 **바뀌지 않는다**
- 백테스트 피드는 `trade_date <= 커서일` 만 준다 (`BacktestFeed` 규약과 같다)
- **과거를 채워야 백테스트가 된다.** 지금 원문은 2026-08-28 부터 3주뿐이다.
  텔레그램은 채널의 과거 글을 날짜로 거슬러 받을 수 있다 (`iter_messages`).
  받아서 **날짜 순서대로** 파이프라인을 돌리면 테마 사전도 그 순서로 자란다

## 7. 비용

`limits.yaml` 의 가벼운 모델 단가($1 / $5 per 1M 토큰) 기준이다. 한국어는
글자당 약 0.7 토큰이다 (2026-09-05 브리핑 실측).

| | 하루 |
|---|---|
| 읽기 입력 — 원문 약 6만 자 ≈ 4만 토큰 | $0.04 |
| 읽기 출력 — 글당 약 50 토큰 × 200건 | $0.05 |
| 묶기 1회 | $0.01 |
| **합계** | **약 $0.10** |

상한 $0.2 안이다. 과거 1년(약 250 거래일)을 채우는 데 한 번에 약 $25 다.

## 8. 병행과 교체

1. 새 파이프라인은 새 테이블에만 쓴다. 옛 키워드 파이프라인은 계속 돈다
2. **판정 사례로 먼저 본다.** 2026-09-18 원문을 넣었을 때
   - 동박적층판(CCL) 이 **하나의 테마로, 1위로** 나온다
   - 그 테마에 두산이 이어진다
   - `저장소`·`동력` 같은 범용 명사가 나오지 않는다
3. 2주 병행하며 나란히 비교한다
4. 나으면 포털 정보수집 탭과 급등 알림을 새 테이블로 옮기고 옛 것을 멈춘다
